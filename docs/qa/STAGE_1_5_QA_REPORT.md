# VLR Resume Studio — Stage 1.5 QA and stabilization

## Executive summary and release gate

**Final decision: PASS for the documented local production-build scope.** All required local gates and critical workflows passed; no known P0/P1 defects remain. Stabilization preserves the existing React/TypeScript/Vite, Zod, Dexie, Zustand, React PDF and PDF.js architecture. No Typst, AI integration, authentication, backend or deployment was introduced.

The baseline was clean at `b7c5f80d09bf54ce2f1b22a2f3a6cf8e1bf9ff96` on `feat/resume-studio-mvp`. Remote references were fetched and PR [#2](https://github.com/VLR-Technologies/vlr-resume-studio/pull/2) was open and unmerged, targeting `main`; stabilization continues that branch. The tested source snapshot is `7a3211284e6b41899242fbd42bb854c7966c6982` (final application fixes, test synchronization and CI calibration); subsequent QA configuration/report-only updates, if any, are identified in the delivery section. No unrelated user edits were present at the start.

Eighteen reproducible application defects were fixed: two P0, four P1 and twelve P2. The most consequential changes prevent UUID-shaped career text from being rewritten, history from being silently trimmed on merge, stale revision restores from overwriting another tab, and old save controllers from erasing newer draft tracking. [BUG_FIX_LOG.md](BUG_FIX_LOG.md) records reproduction, root cause, fix and regression for every issue.

## Environment, scope and reproducibility

- Local host: macOS 26.6.1 (25G76), Node 22.23.1, npm 10.9.8; locked dependencies installed with `npm ci`.
- Production Vite build served on isolated `http://127.0.0.1:4173`; manual fictional workspace on port 4175. The user's existing port 4174 workspace was not edited or cleared.
- Playwright projects: desktop Chromium 1440×1000; mobile Chromium using iPhone 13 emulation; desktop Firefox 1440×1000; desktop WebKit 1440×1000. Actual engine versions: Chromium 156.0.8078.4, Firefox 157.0 and WebKit 27.2. Per-project versions and observed timings are retained in `EVIDENCE_SUMMARY.json`.
- Fixtures: `tests/fixtures/qa-profiles.ts` contains fictional German working student Mara Weiß, software/AI professional Jonas García, and researcher Dr Élodie Martin. Complete career histories and small/medium/large workloads contain no private user data.
- Browser tests use disposable contexts or temporary persistent profiles. Quota/open failures are injected only inside their test contexts. Restart tests close the actual selected engine and reopen the same disposable browser profile.
- Large generated outputs are ignored under `qa-artifacts/` and `test-results/`. Source fixtures, assertions, PDF inspection script, and compact result summaries are committed.

Reproduce the required gates:

```bash
npm ci
npm run lint
npm run typecheck
npm run format:check
npm test
npm run build
npx playwright install --with-deps chromium firefox webkit
npm run test:e2e
npm audit --audit-level=moderate
git diff --check
```

For independent PDF verification, use Python with `pdfplumber`, `pypdf`, Pillow and Poppler available, then run `python3 scripts/qa/inspect_pdfs.py` after `npm test`. It extracts every glyph, checks embedded font descriptors and page bounds, renders representative matrices with Poppler and builds contact sheets. Those outputs are evidence for visual review, not a substitute for it.

## PDF and visual findings

The 40-case matrix is four templates × empty, minimal, one-page, two-page, long-text, maximum/legacy-Letter design, minimum/alternate-font design, student, professional and researcher. One/two-page fixtures assert exact counts; complete personas assert 3–5 pages. All extracted item bounds, dimensions, names/titles, font styles, URI annotations and safe filenames are checked. Very long descriptions/bullets/URLs and European Unicode exercise continuation and wrapping. No expected text is deliberately removed to meet a page count.

Independent `pypdf` and `pdfplumber` checks inspected **40 PDFs / 116 pages**, embedded font streams and every non-whitespace glyph's bounds: zero out-of-page glyphs, no unintended blank pages. Poppler rendered all pages in persona, long-text, bounds, compact, one-page and two-page cases. Four contact sheets and representative larger page images were visually reviewed. QA-013 was found by strict layout checks and fixed without relaxing the assertions. Visual inspection also found QA-018: a short experience header separated from its description; page-level headers now reserve space for following text while long descriptions remain breakable. The 12 persona and 4 maximum-design cases assert each short entry title and the start of its description share a page. See [React PDF wrapping guidance](https://react-pdf.org/docs/v4/advanced/page-wrapping).

Observed hierarchy, margins, glyph rendering, long-title wrapping, section order and link appearance are readable in representative normal layouts. Maximum 40mm margins/16pt body/2× leading deliberately spread content over more pages; tiny 8pt/8mm settings deliberately create dense pages. Complete all-evidence profiles can finish with a short continuation page. These are documented consequences of selected content/settings, not hidden blank pages or an automatic page-fitting guarantee.

Browser persona tests independently parse downloaded PDFs with PDF.js, compare total page count to exact proof status and preserve underlying profile/selections after all template changes. Proof and download share `generatePdf` and font/model inputs; matching page count plus shared code is evidence of layout consistency, not a pixel-by-pixel binary comparison (PDF metadata varies). Continuous HTML view intentionally has no paginated page-break promise.

## Security, privacy and recovery findings

- `npm audit --audit-level=moderate`: zero vulnerabilities in the locked 360-package audit. No dependency was added for stabilization.
- React renders career text as text; no `dangerouslySetInnerHTML` path was found. Actual script/image-markup payload remains inert in the preview; `javascript:` URLs fail validation and leave stored data unchanged.
- Imports reject unsafe object keys/prototype pollution paths, aliases/custom YAML tags, excessive nesting/size, malformed JSON/YAML, duplicate keys/IDs, bad references, unsupported future versions and invalid template configuration. The upload path is capped at 5MB before parsing; typed record limits and review truncation bound processing. This is tested input hardening, not an exhaustive adversarial penetration test.
- Replacement and merge preflights are transactional; failed/interrupted writes preserve the existing workspace. Replacement requires a downloaded native recovery backup and review acknowledgement. New-record import remaps references without changing UUID-like authored content.
- Production workflows under the configured static-host CSP successfully load bundled fonts/PDF worker and generate WASM-assisted PDF layouts. Local workflows observed no off-origin data requests. No runtime secret, telemetry, remote AI endpoint or upload service was found in the source. The docs link is an intentional external navigation.
- IndexedDB is local browser storage, not encryption or a permanent backup. Settings explicitly disclose eviction, private browsing, site-data clearing and shared-browser risks. Startup failure/retry and quota rejection are tested without deleting existing data.
